How this app works

What it reads, what it asks, what an empty panel means, and what the appliance did here.

1 · The data

Everything comes from the impromptu realm. Nothing about music is stored in advance: the catalogue is fetched when a query traverses it and cached, so there is no import to run and nothing going stale on a shelf.

TypeWhere it comes fromFreshness
MusicalComposer
MusicalWork		Open Opus, a free keyless catalogue of about 150 well-known composers. Fetched on demand through COMPOSED_BY, HAS_COMPOSER and HAS_WORK.cached 30 days — a composer’s dates do not move
MusicalRecordingA web search restricted to youtube.com/watch, through the research realm. Each hit’s URL is the watch link.cached 7 days

MusicalEra		Nothing is stored. The words you type are the key, pinned inline, and the works are generated against them.cached 7 days per distinct request
MusicalListen
MusicalWorkRating
MusicalTaste
MusicalListener		Yours, stored in your world’s graph. Written when you press play, rate something, or tell Maestro a boundary.live

prePiano — the “period instruments” badge — is computed from the catalogue’s own death year, not judged by a model: true when the composer died before 1850.

2 · The questions

Every named view this app runs, with the Virtual Cypher that actually executes, read back from the server. Virtual joins (OPENS_WITH, HAS_WORK, HAS_RECORDING, SIMILAR_TO, SUGGESTS, INFLUENCED_BY) materialise when a query traverses them — the fetch happens inside the query, not before it.

SomethingToHearFast

Works that answer a listening request — titles only, no recording lookup, answers quickly.

Parameters: ask

MATCH (lr:ListeningRequest {request: $ask})-[:OPENS_WITH]->(w:MusicalWork)
RETURN DISTINCT w.composer AS Composer, w.title AS Work, w.genre AS Genre
ORDER BY Composer ASC, Work ASC

SomethingToHear

Works that answer a listening request in your own words — no ratings needed, each with a recording.

Parameters: ask

MATCH (lr:ListeningRequest {request: $ask})-[:OPENS_WITH]->(w:MusicalWork)
MATCH (w)-[:HAS_RECORDING]->(r:MusicalRecording)
WITH w, head(collect(DISTINCT r)) AS rec
RETURN w.composer    AS Composer,
       w.title       AS Work,
       w.genre       AS Genre,
       rec.title     AS Performance,
       rec.url       AS Recording
LIMIT 8

ComposersOfEra

Every catalogued composer of one style period, with dates and a portrait.

Parameters: era

MATCH (e:MusicalEra {name: $era})-[:HAS_COMPOSER]->(c:MusicalComposer)
RETURN c.completeName AS Composer,
       c.name         AS ShortName,
       c.birth        AS Born,
       c.death        AS Died,
       c.prePiano     AS PeriodInstruments,
       c.portrait     AS Portrait,
       c.composerId   AS ComposerId
ORDER BY Born ASC, Composer ASC

MeetAComposerFast

A composer's best-known works from the catalogue — titles only, instant.

Parameters: composerId

MATCH (c:MusicalComposer {composerId: $composerId})-[:HAS_WORK]->(w:MusicalWork)
MATCH (w)-[:COMPOSED_BY]->(full:MusicalComposer)
RETURN full.completeName AS Composer,
       full.portrait     AS Portrait,
       full.epoch        AS Period,
       full.prePiano     AS PeriodInstruments,
       w.workId          AS WorkId,
       w.title           AS Work,
       w.genre           AS Genre,
       w.searchQuery     AS SearchQuery
ORDER BY Genre ASC, Work ASC

ComposerLineage

Composers held to have shaped this one's music — the line backwards, and older music you may be half-ready for.

Parameters: composer

MATCH (c:MusicalComposer {name: $composer})-[:INFLUENCED_BY]->(earlier:MusicalComposer)
RETURN earlier.completeName AS Influence,
       earlier.epoch        AS Period,
       earlier.birth        AS Born,
       earlier.death        AS Died,
       earlier.prePiano     AS PeriodInstruments
ORDER BY Born ASC

WorkRecommendations

Top 5 works you'd like — each with a recording to hear.

Parameters: none

MATCH (me:AssistantUser)-[:RATED]->(rt:MusicalWorkRating) WHERE rt.rating >= 8
MATCH (rt)-[:SIMILAR_TO]->(w:MusicalWork)
WHERE NOT EXISTS { (me)-[:RATED]->(seen:MusicalWorkRating) WHERE seen.workId = w.workId }
MATCH (w)-[:HAS_RECORDING]->(r:MusicalRecording)
WITH w, count(DISTINCT rt) AS overlap,
     head(collect(DISTINCT r)) AS rec
RETURN w.composer AS Composer,
       w.title    AS Work,
       rec.title  AS Performance,
       rec.url    AS Recording,
       overlap    AS LovedWorksPointingHere
LIMIT 5

TasteBasedRecommendations

Works matching your overall taste — each with a recording to hear.

Parameters: none

MATCH (me:AssistantUser)-[:HAS_MUSICAL_TASTE_SUMMARY]->(ts:MusicalTasteSummary)
MATCH (ts)-[:SUGGESTS]->(w:MusicalWork)
WHERE NOT EXISTS { (me)-[:RATED]->(seen:MusicalWorkRating) WHERE seen.workId = w.workId }
MATCH (w)-[:HAS_RECORDING]->(r:MusicalRecording)
WITH w,
     head(collect(DISTINCT r)) AS rec
RETURN w.composer AS Composer,
       w.title    AS Work,
       w.genre    AS Genre,
       rec.title  AS Performance,
       rec.url    AS Recording
LIMIT 8

MyListening

Where you have got to as a listener — how much you know, how hard you want to be pushed, and what you have heard.

Parameters: none

MATCH (me:AssistantUser)
OPTIONAL MATCH (me)-[:LISTENS_AS]->(l:MusicalListener)
OPTIONAL MATCH (me)-[:RATED]->(r:MusicalWorkRating)
OPTIONAL MATCH (me)-[:HEARD]->(h:MusicalListen)
OPTIONAL MATCH (me)-[:HAS_TASTE]->(t:MusicalTaste)
RETURN coalesce(l.knowledge, 'not yet read')        AS Knowledge,
       coalesce(l.challenge, 0)                     AS ChallengeAppetite,
       count(DISTINCT r)                            AS WorksRated,
       count(DISTINCT h)                            AS WorksHeard,
       count(DISTINCT t)                            AS StancesStated

MyMusicalStances

What you have said you love, avoid, or are curious about — by form, period, instrument or practice.

Parameters: none

MATCH (me:AssistantUser)-[:HAS_TASTE]->(t:MusicalTaste)
RETURN t.stance  AS Stance,
       t.kind    AS Dimension,
       t.value   AS Value,
       t.because AS Because,
       t.statedAt AS Stated
ORDER BY CASE t.stance WHEN 'curious' THEN 0 WHEN 'loves' THEN 1 WHEN 'likes' THEN 2
                       WHEN 'avoids' THEN 3 ELSE 4 END, Value ASC

WhatIHaveHeard

Your listening history — the work, the performance, and whether you heard it through.

Parameters: none

MATCH (me:AssistantUser)-[:HEARD]->(h:MusicalListen)
RETURN h.heardAt     AS Heard,
       h.composer    AS Composer,
       h.title       AS Work,
       h.performance AS Performance,
       h.finished    AS HeardThrough,
       h.url         AS Recording
ORDER BY Heard DESC
LIMIT 50

3 · When it looks wrong

What you seeWhat it means
“What you love” is emptyThose two views anchor on works you rated 8 or more. With no ratings there is nothing to anchor on, and the view says so rather than guessing. Use Ask for something, which needs no history.
An ask returns nothingThe generator named works the catalogue could not identify, so they were dropped — it holds only about 150 composers. The engine reports this as RESOLUTION_DROPPED with a sample of what it lost. A famous composer’s neglected work resolves where an obscure composer’s masterpiece does not.
“No recording found”The search found no youtube.com/watch result, or the research realm is not installed and BRAVE_API_KEY is unset. Everything else keeps working; only listen and score links go quiet.
A figure disagrees with Open OpusCatalogue reads are cached for 30 days. Inside that window a mismatch is the cache, not a bug.
Maestro names performers but gives no linkDeliberate. In conversation he has no search running, and a model asked for a recording will invent a watch URL that looks exactly real. He names the performance instead; the surface attaches the real link.

4 · What made this possible

The composer wall is one HTTP call and no model call at all: an era, its composers, their dates and portraits arrive as a Cypher traversal of a catalogue that was never imported. On a conventional stack that is an ingest job, a schema and a staleness window.

“Forty minutes, nothing soothing” is answered by generating inside the query and resolving each suggestion onto the catalogue’s own ids, so a generated recommendation dedupes against what you have already heard. The generation, the resolution and the anti-join are one question rather than a pipeline.

This page has no backend. It asks the world by view name at load; there is no service to deploy or keep patched, and the Cypher above is the Cypher that ran.

The limits are on this page too, which is the point of it: a catalogue of ~150 composers, a recommendation that is a model’s judgement rather than a fact, and an influence edge that is generated rather than catalogued — shown as a scholarly view, never as a date.
